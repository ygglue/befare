# AGENTS.md: getting up to speed on BeFare

Read this first. It's the short version of everything in `docs/`, plus what isn't written anywhere else. For setup and build commands, see the [README](README.md#setup).

## What BeFare is

An **offline-first tricycle fare estimator for Puerto Princesa City** (Palawan, Philippines). The user drops a start pin (or uses GPS) and a destination pin. The app routes over the city's roads **on the device** and shows the official fare from **City Ordinance No. 1185 (2021)**. A **Verify** screen shows how the fare was worked out and the source document behind it.

- v1 is fully offline: map, routing, fares and GPS. Coverage is the urban area from the city proper to Sta. Lourdes.
- Phase 2 (not started) adds online **plate lookup and reviews** on Supabase. It needs permission from the City government / LTFRB first. See `docs/PLATE_LOOKUP.md`.

## Rules that matter

1. **Fare and routing logic only in `shared/`.** Platform code never does fare math. It calls `EstimateService.estimate(start, end, bandId)` and shows the result.
2. **Fares are data, not code.** Fare rules live in `data/fares/fares.json`, generated by `scripts/build_fares.py` from the hand transcription in `docs/sources/*.md`. Edit the transcription, never the JSON. The script checks every cell against the matrix's pattern.
3. **Provenance is the product.** Every breakdown line and fare rule links to a source. Don't show a number the Verify screen can't explain. Unverified assumptions are flagged in the data (`kmRoundingVerified: false`, `verified: false`, `currentBand.id: null`) and listed as assumptions in Verify. Don't silently "fix" them.
4. **Money is integer centavos.** No floating-point currency.
5. **Offline means offline.** The apps make no network calls. Tiles, style, fonts, sprites, graph, mask and fares are all bundled. The style JSON must contain no `http` URLs.
6. **Tricycle fares are set by the city government, not LTFRB.** LTFRB covers jeepneys, taxis, vans and buses (phase 2).
7. **Accessibility is required.** Text ≥ 4.5:1 contrast, 48dp/44pt touch targets, labels/states for screen readers, layouts that survive large text. On Android, give overlay `Surface`s an explicit `contentColor`, or text renders dark on dark.
8. **Decisions go in ADRs** (`docs/adr/`). Read them before revisiting platform (KMP), map (MapLibre + PMTiles), backend (Supabase) or coverage choices.

## How the fare works (Ordinance 1185)

- A table by **whole kilometre (1–20)** × **gas-price band** (Regular, then ₱60–70 up to ₱110–120 per litre). Each band is ₱2 more than the one before. Regular is ₱12 for the first 2 km, then +₱2 per km.
- Route distance is the road distance from A*. A started kilometre counts as a full km (**assumed**, not stated on the matrix).
- 20% discount for senior citizens, PWDs and students.
- The current gas band isn't known offline. The bundle has `currentBand` (unset for now) and the user can change the band.
- Still open (needs the ordinance text): partial-km rounding, discount rounding, band edges, effective date. See `docs/sources/pp-city-tricycle-ord1185-2021.md`.

## Verifying changes

- `./gradlew :shared:jvmTest` runs fare math and real-graph routing tests (e.g. Robinsons → Baywalk).
- Hand-check fares against the matrix photo: San Jose → downtown ≈ 6 km = ₱20 regular / ₱16 discounted.
- Look at both apps after UI changes. Screenshots: `xcrun simctl io booted screenshot x.png` and `adb exec-out screencap -p > x.png`.
- GPS: `xcrun simctl location booted set LAT,LON` and `adb emu geo fix LON LAT` (**longitude first**). Inside the area: San Jose `9.7943,118.7487`. Outside: Sabang `10.197,118.89`.

## Gotchas (learned the hard way)

- **The shared module has an Android target**, so every Gradle build, iOS ones included, needs an Android SDK path in `local.properties` (or `ANDROID_HOME`). `local.properties` is machine-specific and git-ignored.
- After changing Kotlin in `shared/`, rebuild the XCFramework before building in Xcode. After adding Swift files or editing `project.yml`, re-run `xcodegen generate`. The `.xcodeproj` is generated and ignored.
- `xcrun simctl`/Simulator screenshots can lag a second or two behind taps. Two quick taps on the map can register as a double-tap zoom.
- The Android emulator only refreshes its cached GPS position while an app is listening. A `geo fix` sent while BeFare is closed shows up as a stale last-known fix on the next launch. The app ignores cached fixes older than 2 minutes.
- On first launch Android copies the offline data from the APK to app storage (`OfflineData.install`), so the first start takes a few seconds longer.
- MapLibre's logo and attribution are repositioned above the fare card on both platforms (`keepOrnamentsAbove`). Keep them visible: OSM attribution is required by the ODbL.
- Classes declared inside `build.gradle.kts` can't be Gradle task types. Use built-in tasks (e.g. `Sync`) or `buildSrc`.
- Kotlin/Native warns that Xcode is newer than it supports. `kotlin.apple.xcodeCompatibility.nowarn=true` in `gradle.properties` silences this, and it's harmless.
- The fade mask is many stacked polygons with per-feature `opacity`, because MapLibre can't blur fills. The app's coverage check uses the **smoothed** outline (`data/build/coverage-smooth.geojson`) so pins are accepted exactly where the map is clear.

## Working conventions

- Commit only when asked. Write clear, descriptive commit messages. Branch first if work should be reviewed separately.
- Keep `docs/` current when behaviour changes. `docs/MVP.md` tracks how the build differs from the plan.
- Don't commit generated data (`data/build/`, `data/osm/`), `.venv/`, `local.properties` or build outputs.
- OSM data is ODbL: attribution must stay visible in both apps.
